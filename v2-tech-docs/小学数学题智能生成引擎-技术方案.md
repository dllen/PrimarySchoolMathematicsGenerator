# 小学数学题智能生成引擎

> 面向小学 1~6 年级的数学应用题、奥数题自动生成系统  
> 核心目标：**可控生成、数学正确、难度可控、答案可验证、题目可复现、题型可扩展**

---

## 1. 项目背景

传统的数学题生成方式主要有两种：

### 方式一：纯随机模板

```text
随机数字
    ↓
套模板
    ↓
生成题目
```

优点：

- 实现简单
- 性能高
- 不依赖大模型

缺点：

- 题型变化有限
- 难度控制弱
- 容易生成不合理题目
- 奥数题很难生成
- 容易产生大量重复题

### 方式二：LLM 直接生成

```text
年级 + 题型 + 难度
        ↓
       LLM
        ↓
      数学题
```

优点：

- 语言自然
- 题目变化丰富
- 可以快速覆盖大量题型

缺点：

- 数学错误不可完全避免
- 答案可能错误
- 难度不稳定
- 年级适配不稳定
- 题目条件可能不足或冗余

### 本项目采用的方案

```text
数学结构
    ↓
参数生成
    ↓
约束验证
    ↓
自动求解
    ↓
自然语言渲染
    ↓
质量检查
```

核心原则：

> **不要让 LLM 负责数学正确性，让程序负责数学，让 LLM 负责语言。**

# 3. 核心设计原则

## 3.1 数学优先

生成顺序：

```text
数学关系
 ↓
变量
 ↓
约束
 ↓
答案
 ↓
题目文字
```

而不是：

```text
题目文字
 ↓
猜数学关系
```

---

## 3.2 可复现随机

所有题目生成使用 Seed。

```text
seed
 +
templateId
 +
difficulty
 +
problemIndex
```

生成确定的题目。

例如：

```json
{
  "seed": 20260915,
  "templateId": "G3_PRICE_001",
  "index": 10
}
```

以后可以重新生成完全相同的题目。

---

## 3.3 生成与验证分离

```text
Generator
    ↓
Problem
    ↓
Validator
    ↓
Valid / Invalid
```

任何题目都必须通过验证才能进入题库。

# 7. 奥数题核心算法：逆向生成

普通题：

```text
随机参数
 ↓
计算答案
```

奥数题更适合：

```text
确定解题结构
 ↓
确定答案
 ↓
反向构造条件
 ↓
生成题目
 ↓
自动验证
```

例如鸡兔同笼：

```text
x + y = heads
2x + 4y = legs
```

随机：

```text
chicken = 23
rabbit = 12
```

反推：

```text
heads = 35
legs = 94
```

得到：

> 笼子里有一些鸡和兔，共有35个头，94只脚。问鸡和兔各有多少只？

# 12. Random Engine

使用 Seeded Random。

```typescript
export class Random {
  constructor(private seed: number) {}

  int(min: number, max: number): number {
    this.seed =
      (this.seed * 9301 + 49297) % 233280;

    const r = this.seed / 233280;

    return Math.floor(
      min + r * (max - min + 1)
    );
  }

  pick<T>(items: T[]): T {
    return items[
      this.int(0, items.length - 1)
    ];
  }
}
```

# 13. Generator

统一接口：

```typescript
export interface ProblemGenerator {
  generate(
    template: ProblemTemplate,
    options: GenerateOptions
  ): Problem;
}
```

核心逻辑：

```typescript
function generateProblem(
  template: ProblemTemplate,
  random: Random
): Problem {

  for (let i = 0; i < 100; i++) {

    const variables =
      generateVariables(
        template,
        random
      );

    const problem =
      buildProblem(
        template,
        variables
      );

    if (validate(problem)) {
      return problem;
    }
  }

  throw new Error(
    "Unable to generate valid problem"
  );
}
```

核心机制：

```text
Generate
   ↓
Validate
   ↓
失败 → Retry
   ↓
成功
```

# 15. 解题树

奥数题建议增加 Proof Tree。

```text
题目
 ↓
第一步：建立关系
 ↓
第二步：求中间变量
 ↓
第三步：代入
 ↓
第四步：得到答案
```

核心指标：

```text
depth
width
operations
variables
knowledgePoints
```

因此难度可以从数学结构本身计算，而不是人工指定。

# 16. 题目去重

简单的字符串去重是不够的。

例如：

```text
小明有5个苹果。
```

和：

```text
小红有5个苹果。
```

文字不同，但数学结构完全一样。

因此需要：

```text
Question
 ↓
Normalize
 ↓
Math Signature
 ↓
Hash
```

例如：

```text
MULTIPLY(unitPrice, quantity)
```

形成：

```text
templateId
+
mathSignature
+
variables
```

最终生成：

```text
problemHash
```

实现：

- 文字去重
- 数学结构去重
- 参数去重
- 相似题检测

# 17. LLM 的定位

LLM 不参与核心数学计算。

推荐：

```text
Math Engine
     ↓
{
  unitPrice: 8,
  quantity: 6,
  total: 48
}
     ↓
LLM
     ↓
自然语言题目
```

Prompt 要求：

```text
1. 不修改数字
2. 不修改数学关系
3. 不增加新的数学条件
4. 保证答案唯一
5. 符合指定年级阅读能力
6. 不直接输出答案
7. 输出 JSON
```

因此：

> LLM = Natural Language Renderer

而：

> Math Engine = Source of Truth

# 29. 核心技术路线总结

整个项目最重要的技术路线可以浓缩成：

```text
                    Math DSL
                       │
                       ↓
              ┌────────────────┐
              │ Problem Model  │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Generator      │
              │ Random/Reverse │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Constraint     │
              │ Satisfaction    │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Solver         │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Difficulty     │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Validator      │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ Dedup / Search │
              └───────┬────────┘
                      ↓
              ┌────────────────┐
              │ LLM Renderer   │
              └───────┬────────┘
                      ↓
                 Question Bank
```

**核心原则只有一句：**

> **程序生成数学，程序验证数学，LLM 生成语言。**

这样才能同时解决**题目数量、数学正确性、难度控制、年级适配、题目去重和奥数题生成**这几个核心问题。
